# SRS-307.2 — Known failure cause (AO)

> **SRS-307.2, AO, Known failure cause.** The system shall display the cause of failure when a failed extraction's cause is an unreadable file, a file over the size limit, or a missing source file.
>
> **Acceptance:** Given an extraction failed because the file could not be read, When the failure message is displayed, Then it states that the file could not be read.
>
> Traces to: UR-307

## What was built

| Task | File | What it does |
|---|---|---|
| 307.2-1 | `lib/extractions.ts`, `app/api/extractions/[id]/route.ts` | `GET /api/extractions/[id]` also returns `failure_message` for a Failed extraction with a known cause |
| 307.2-2 | `app/(app)/extractions/[id]/page.tsx` | The page shows the cause under **Extraction was not completed.** |
| 307.2-3 | `__tests__/api/known-failure-cause.test.ts` | 6 tests: each known cause gets its message, Other and non-failed extractions get none, messages contain no codes or technical details |

| Stored cause (`extractions.failure_cause`) | Shown to the user |
|---|---|
| Unreadable file | The file could not be read. |
| File too large | The file is larger than the 25 MB size limit. |
| Missing source file | The source file could not be found. |
| Other | *(nothing extra; "Something went wrong. Please try again." is SRS-307.3)* |

**Database:** reuses `extractions.failure_cause`, which the extraction already saves when it fails (SRS-302.1). No schema change.

## Demo

1. On **Contact Extraction**, request an extraction of an **agenda packet** whose text CivicClerk can't read, e.g. **Salem City Council Regular Meeting September 10, 2026 (Packet)**.
2. Open it: the status goes to **Failed**, and the page says **Extraction was not completed.** and **The file could not be read.** *(Acceptance criterion.)*
