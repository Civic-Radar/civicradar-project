# SRS-311.2 — Merge repeated officials (AO)

> **SRS-311.2, AO, Merge repeated officials.** When an extraction finds an official already in the shared list, the system shall update that entry instead of creating a second one.
>
> **Acceptance:**
> * A name match with the same body creates no duplicate entry.
> * The entry shows the most recent title and contact details found.
> * The entry keeps a link to every source document it came from.
>
> Traces to: UR-311

## How it works

Each extraction still saves exactly what its document says, privately for the user (`extracted_officials`, SRS-302.1). After that, each official also goes into the **shared officials list**:

1. Find the governing body of the document's meeting (`documents.meeting_id` → `meetings.body_id`). If the meeting has none and the town has exactly one governing body, use that one (Task 311.2-5).
2. Look for an official with the **same name, ignoring letter case and extra spaces, in the same body**. This is the same rule as the database's unique index `officials_name_body_uq (body_id, lower(full_name))`, so the database also refuses a duplicate.
3. **Found:** update that entry with the title, role, email, and phone this document found. A detail this document didn't give keeps its old value; nothing is blanked out. `details_document_id` points to this document.
4. **Not found:** add a new entry.
5. Link the document to the official (`official_sources`, one row per official and document).

Example: the Oct 19 hearing notice gives "Maureen Elizabeth Fisher, City Clerk" with no contact details. The Oct 15 agenda gives "Acting City Clerk", mfisher@salem.com, and 978-619-5614. After both are extracted, the shared list has **one** Maureen Elizabeth Fisher with the newest title and both contact details, linked to both documents.

## Notes
- **Meetings with no governing body** (retrieval saves some, like Salem's special meetings, as "General" with `body_id` NULL) belong to the town's only governing body (Task 311.2-5). In a town with several bodies they are left out, since the body can't be known.
- **Names must match exactly** (ignoring case and spacing). "Merkl" and "Alice Merkl" stay two entries, because the document doesn't say they are the same person.
- If the shared list can't be updated, the extraction still completes: its own results are already saved.
- Contact details are never written to the logs (SRS-310.3).
