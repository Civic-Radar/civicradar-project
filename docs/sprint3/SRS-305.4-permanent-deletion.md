# SRS-305.4 — Permanent deletion (AO)

> **SRS-305.4, AO, Permanent deletion.** The system shall permanently delete the extraction when the user confirms deletion.
>
> **Acceptance:** Given the deletion confirmation is displayed, When the user confirms, Then the extraction no longer appears in the list and cannot be opened.
>
> Traces to: UR-305

## What was built

| Task | File | What it does |
|---|---|---|
| 305.4-1 | `app/api/extractions/[id]/route.ts` | `DELETE /api/extractions/[id]` deletes one of the user's extractions. **Database:** its officials go with it through the existing `on delete cascade` on `extracted_officials.extraction_id`. Another user's extraction answers 403 (SRS-310.2) and stays; an unknown id answers 404 |
| 305.4-2 | `app/(app)/extractions/page.tsx` | The deletion confirmation (SRS-305.2) gets a **Delete extraction** button. Confirming deletes it and removes it from the list |
| 305.4-3 | `__tests__/api/permanent-deletion.test.ts` | 7 tests: after confirming, it's gone from the list, its page answers 404, its officials are gone, other extractions stay, another user can't delete it |

The shared officials list (SRS-311) is not affected: it is built from documents, not from one user's extraction.

## Demo

1. Open **Saved Extractions** and note an extraction's address (e.g. `/extractions/24`).
2. Click **Delete**, then **Delete extraction** in the confirmation.
3. It disappears from the list. *(Acceptance criterion.)*
4. Open its old address: it can't be opened ("Extraction not found."). *(Acceptance criterion.)*

## Notes
- The "Extraction deleted." and "could not be deleted" messages are SRS-305.5 and SRS-305.6, not in this sprint. If a deletion fails, the extraction stays listed and the error is shown.
