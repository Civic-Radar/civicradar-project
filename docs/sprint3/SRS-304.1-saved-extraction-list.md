# SRS-304.1 — Saved extraction list (AO)

> **SRS-304.1, AO, Saved extraction list.** The system shall list the signed-in user's saved extractions, with each one's source document title and extraction date, when the user opens the Saved Extractions page.
>
> **Acceptance:** Given the user has two saved extractions, When the user opens the Saved Extractions page, Then both are listed, each with its source document title and extraction date.
>
> Traces to: UR-304

## What was built

| Task | File | What it does |
|---|---|---|
| 304.1-1 | `app/api/extractions/route.ts` | `GET /api/extractions?saved=1` returns only the user's saved extractions (status Completed), newest extraction first. Without `saved=1` the list is unchanged |
| 304.1-2 | `app/(app)/extractions/page.tsx`, `lib/extractions.ts` | **Saved Extractions** page at `/extractions`: each saved extraction with its source document title and "Extracted MM/DD/YYYY h:mm AM"; each opens its stored results |
| 304.1-3 | `app/components/ContactsTabs.tsx`, `app/components/Sidebar.tsx` | A **Saved** tab in the Contacts area opens this page (the sidebar has one **Contacts** item) |
| 304.1-4 | `__tests__/api/saved-extractions.test.ts` | 6 tests: two saved extractions are both listed with title and date, newest first, only Completed ones, only the user's own |

**Database:** reuses `extractions` (`user_id`, `status`, `source_document_title`, `completed_at`). No schema change.

**What counts as saved:** a completed extraction, the one with stored results. Queued, Processing, and Failed requests stay on the **Contact Extraction** page under "My extraction requests".

**Extraction date:** when the extraction finished (`completed_at`).

## Demo

1. Log in and complete two extractions on **Contact Extraction**.
2. Open **Contacts** in the sidebar, then the **Saved** tab.
3. Both are listed, each with its document title and extraction date. *(Acceptance criterion.)*
4. Click one: its officials open, read from the database without running a new extraction.
