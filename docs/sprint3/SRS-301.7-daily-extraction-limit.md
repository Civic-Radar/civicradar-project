# SRS-301.7 — Daily extraction limit (AO)

> **SRS-301.7, AO, Daily extraction limit.** The system shall refuse a new extraction request, and display "You've reached today's extraction limit. Please try again tomorrow.", when the signed-in user has already requested the daily limit of extractions (10 by default) that day.
>
> **Acceptance:** Given a user has requested 10 extractions today, When the user requests another, Then no extraction request is created and "You've reached today's extraction limit. Please try again tomorrow." is displayed.
>
> Traces to: UR-301

## Why
Every extraction calls the Claude API on the project's key. Once the site is live and signup is open, any signed-in user could run extractions without limit and use up the credits (raised by MS before going live). A run only ever runs a new Queued request once, so capping requests per user per day caps the Claude calls.

**The limit** is 10 per user per day. Change it with `EXTRACTION_DAILY_LIMIT` in `.env.local` (a positive whole number). **The day** is a calendar day in the pilot municipality's time zone (America/New_York), from midnight.

No schema change.

## Demo

1. In `.env.local`, set `EXTRACTION_DAILY_LIMIT=2` and restart `npm run dev` (so the demo doesn't need 10 extractions).
2. On **Contacts → Request**, request two extractions.
3. Request a third: **"You've reached today's extraction limit. Please try again tomorrow."** appears and **Request extraction** stays disabled. *(Acceptance criterion.)*
4. In Supabase, no third extraction was created.
5. Remove the line from `.env.local` afterwards (back to 10).
