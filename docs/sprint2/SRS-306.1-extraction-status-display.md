# SRS-306.1 — Extraction status display (AO)

> **SRS-306.1, AO, Extraction status display.** The system shall display the extraction's current status (Queued, Processing, Completed, or Failed) while the user views an extraction request.
>
> **Acceptance:** Given an extraction request with status Processing, When the user views the request, Then "Processing" is displayed as its status.
>
> Traces to: UR-306

## What was built

| Task | File | What it does |

| 306.1-2 | `app/api/extractions/[id]/route.ts` | `GET` returns one of the signed-in user's extractions with its current status |
| 306.1-3 | `app/(app)/extractions/[id]/page.tsx` | Extraction page at `/extractions/<id>` showing the status; re-checks every 3 seconds while Queued or Processing |
| 306.1-4 | `app/(app)/extract/page.tsx` | Each request in "My extraction requests" links to its page |
| 306.1-5 | `__tests__/api/extraction-status.test.ts` | 12 tests: each of the four statuses is returned, a status change shows up, other users' extractions are not returned |
| 306.1-6 | `lib/supabase.ts` | Supabase reads are never cached by Next.js, so a status change shows up on the next check. This file is shared, so every route now reads current data |

## Demo

The extraction worker (SRS-302.1) isn't built yet, so new requests stay **Queued**. To show every status, change it by hand in Supabase while the page is open; the page updates within 3 seconds.

1. Log in, open **Contact Extraction**, and request an extraction (or use an existing one).
2. Click the request under **My extraction requests**. The page shows **Status: Queued**.
3. In the Supabase SQL Editor, using the request number from the page:
   ```sql
   update extractions set status = 'Processing' where extraction_id = 1;
   ```
   The page changes to **Processing** on its own. *(This is the acceptance criterion.)*
4. Then:
   ```sql
   update extractions set status = 'Completed', completed_at = now() where extraction_id = 1;
   ```
   The page shows **Completed** and a **Finished** time.
5. To show **Failed** (the schema requires a failure cause for Failed):
   ```sql
   update extractions set status = 'Failed', failure_cause = 'Other', completed_at = now() where extraction_id = 1;
   ```

To reset:
```sql
update extractions set status = 'Queued', failure_cause = null, completed_at = null where extraction_id = 1;
```
