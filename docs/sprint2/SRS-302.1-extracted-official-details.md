# SRS-302.1 — Extracted official details (AO)

> **SRS-302.1, AO, Extracted official details.** The system shall display each extracted official's name, title, role, email address, and telephone number, each next to its field name, when the user opens a completed extraction.
>
> **Acceptance:** Given an extraction found an official with a name, title, role, email address, and telephone number, When the user opens the extraction, Then all five values are displayed, each next to its field name.
>
> Traces to: UR-302

## How it works

1. The user requests an extraction (SRS-301.4). It starts **Queued**.
2. The server claims it (**Processing**) and fetches the document's text from CivicClerk (`GetMeetingFileStream(fileId=…, plainText=true)`).
3. The text goes to the **Claude API**, which returns each official's name, title, role, email, and phone. Anything not written in the document comes back empty.
4. The officials are saved in `extracted_officials`, and the extraction becomes **Completed**. If any step fails, it becomes **Failed** with a cause.
5. The extraction page (`/extractions/<id>`) updates on its own and lists each official, with all five fields next to their labels. A missing detail shows **Not found**.

## Setup (one time)

1. In `.env.local`, add your key (see `.env.example`):
   ```
   ANTHROPIC_API_KEY="sk-ant-..."
   ```
   Restart `npm run dev` after adding it. Optional: `ANTHROPIC_MODEL` picks the model (default `claude-haiku-5-5`).
2. In the Supabase SQL Editor, run `supabase/seed_extraction_salem_documents.sql`. It's safe to run more than once.

## Demo

1. Log in and open **Contact Extraction**.
2. Select **Joint Public Hearing with the Planning Board Monday October 19, 2026**, then **Request extraction** and **Confirm**.
3. Click the request. The status goes **Queued → Processing → Completed** in a few seconds.
4. Under **Officials found**, each official is a separate entry showing **Name, Title, Role, Email address, Telephone number**. Details the document didn't give show **Not found**.
5. Prove it in Supabase:
   ```sql
   select e.extraction_id, e.status, o.full_name, o.title, o.role, o.email, o.phone
   from extractions e join extracted_officials o using (extraction_id)
   order by e.extraction_id desc, o.extracted_official_id;
   ```

**Notes:**
- Each run costs a fraction of a cent with Haiku.
- The two Sprint 1 placeholder PDFs had no real file, so they are gone: re-run `supabase/seed_extraction_demo.sql` once to remove them. It keeps the Word file that shows the unsupported-format message (SRS-301.5).
- Officials' details are never written to the logs (SRS-310.3).
