# SRS-310.2 — Ownership check (AO)

> **SRS-310.2, AO, Ownership check.** The system shall deny a request to view, search, or delete an extraction when the signed-in user does not own that extraction.
>
> **Acceptance:** Given user A owns extraction 42, When user B requests extraction 42 by changing the page address, Then the system returns an access-denied response.
>
> Traces to: UR-310

## What was built

| Task | File | What it does |
|---|---|---|
| 310.2-1 | `app/api/extractions/[id]/route.ts`, `lib/extractions.ts` | `GET` answers **403** with "You don't have access to this extraction." when the extraction belongs to someone else. Nothing about it is returned |
| 310.2-2 | `lib/extraction/runExtraction.ts`, `app/api/extractions/[id]/run/route.ts` | Running someone else's extraction answers **403** too, and never runs it |
| 310.2-3 | `app/(app)/extractions/[id]/page.tsx` | The extraction page shows **Access denied** with the message and a link back to the user's own requests |
| 310.2-4 | `__tests__/api/ownership-check.test.ts` | 8 tests: user B is denied user A's extraction 42 (view and run), user A still gets it, and an id that doesn't exist is still 404 |

| Request | Owner | Another user | No such extraction |
|---|---|---|---|
| `GET /api/extractions/<id>` | 200 | **403** | 404 |
| `POST /api/extractions/<id>/run` | 200 / 409 | **403** | 404 |

## Demo

You need two accounts.

1. Log in as **user A**, open **Contact Extraction**, request an extraction, and open it. Note the number in the address, for example `/extractions/42`.
2. Log out, and log in as **user B**.
3. Type user A's address into the browser: `http://localhost:3000/extractions/42`.
4. The page shows **Access denied — You don't have access to this extraction.** None of user A's document or officials appear. *(This is the acceptance criterion.)*
5. Log back in as user A and open the same address: the extraction shows as normal.

## Notes
- Search (SRS-309) and delete (SRS-305) aren't built yet. When they are, they should answer 403 the same way, using `ACCESS_DENIED_MESSAGE` from `lib/extractions.ts`.
- An id that doesn't exist at all still answers 404, so "not yours" and "doesn't exist" stay distinguishable for the owner of the data.
